# Liam Portfolio｜網站製作方案 v1

實作狀態：私人編輯器、Supabase 草稿／媒體流程、版本快照與回復程式，以及公開閱讀介面已建立。超出頁面高度的內容可捲動；頁角／手機翻頁手勢、手機底部固定閱讀控制、圖片觸控縮放與拖動、點擊後載入 YouTube／Vimeo 影片、目錄作品縮圖及預覽溢出提示已實作。依實際畫面測量的自動分頁、長段落自動拆分及依剩餘空間重新排組仍未完成，因此過長內容以頁內捲動確保不被裁切。正式使用前仍須完成下方 Supabase 帳號與環境設定，並驗證 Netlify 部署相容性。

本地啟動：`npm install` 後執行 `npm run dev`。

預設作品內容是可自行修改的示範草稿。未設定 Supabase 時，首頁會明確顯示示範模式，`/admin` 會顯示設定說明，不會假裝已儲存或發佈。

### 第一次設定私人編輯器

1. 建立 Supabase 專案，在 Authentication 設定中停用公開註冊，啟用登入，並手動建立 Liam 的管理者帳號。確認該帳號使用的電子郵件。
2. 開啟 [`supabase/migrations/202610120001_portfolio_editor.sql`](./supabase/migrations/202610120001_portfolio_editor.sql) 檔案，複製檔案內的**全部 SQL 內容**，貼到 Supabase Dashboard → SQL Editor，再按 Run 執行一次。請勿把檔案路徑 `supabase/migrations/202610120001_portfolio_editor.sql` 貼進 SQL Editor；路徑不是 SQL 指令，會造成 `syntax error at or near "supabase"`。
3. 在 Supabase Authentication → Users 複製 Liam 帳號的 UUID，並在 SQL Editor 指派唯一管理者：

   ```sql
   update public.portfolio_sites
   set owner_id = '貼上 Liam 帳號的 UUID'
   where id = '00000000-0000-4000-8000-000000000001';
   ```

4. 複製 `.env.example` 為 `.env.local`，填入 Supabase 專案 URL、anon／publishable key，以及 Liam 帳號電子郵件。專案 URL 請從 Supabase Dashboard 的 **Project Settings → API → Project URL** 複製，格式通常為 `https://<project-ref>.supabase.co`。這裡只能填專案的根網址，網域後不可帶任何路徑（例如 `/dashboard/...`、`/project/...`、`/rest/v1`），也不要填 Supabase Dashboard 網址（例如 `https://supabase.com/dashboard/...`）、資料庫連線字串或只填 project ref；URL 必須是部署網站的伺服器可連線的專案 API 網址。

   ```text
   NEXT_PUBLIC_SUPABASE_URL=https://你的專案.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=你的 anon 或 publishable key
   PORTFOLIO_ADMIN_EMAIL=liam@example.com
   ```

   不要把資料庫密碼或 `service_role` key 放進前端環境變數，也不要提交 `.env.local`。

5. 執行 `npm run dev`，開啟 `http://localhost:3000/admin`，用 Liam 的帳號登入。編輯內容會自動存成私人草稿；圖片會先上傳到私人 bucket。
6. 在編輯器右側預覽，確認發佈摘要後選擇「Publish snapshot」。已發佈圖片會另存為 WebP 公開衍生檔；草稿原圖維持私人。到「Publication history」可以預覽舊快照或將其設回公開版本，草稿不會被覆蓋。

若首次登入顯示帳號未指派，請確認 `.env.local` 的郵件完全符合 Supabase Auth 帳號，並重新檢查第 3 步的 UUID。修改 `.env.local` 後需重新啟動 Next.js。

正式部署時，將同樣三個環境變數設定在 Netlify 的環境設定中；不要提交任何金鑰。此專案的 `netlify.toml` 只將 `NEXT_PUBLIC_SUPABASE_ANON_KEY` 從 Netlify Secrets Scanning 的掃描結果中排除，因為 Supabase anon／publishable key 是設計上會公開的用戶端金鑰；其他秘密掃描仍保持啟用。此設定只適用於該環境變數確實存放 anon／publishable key 的情況，絕不可放入 `service_role` key 或資料庫密碼。提交 `netlify.toml` 後需觸發新的 Production deploy。Netlify 上線前須另外驗證 Next.js App Router、Server Actions、`sharp` 圖片處理、檔案上傳限制及 Supabase 回呼網址設定。

網站定位為「Liam 的線上作品集書」：訪客以翻書方式看作品，Liam 在私人後台編輯；按下發佈後更新內容，無須重新部署。

## 1．產品範圍

網站只有一位管理者 Liam，包含兩個介面：

- **公開作品集：** 封面、目錄、關於我、作品章節、聯絡封底。
- **私人後台：** 編輯內容、管理圖片、調整排序、預覽、發佈與回復版本。

所有公開內容都在首頁網址內閱讀。翻頁、開啟目錄或切換作品時，網址保持不變；不提供作品獨立網址、分享按鈕或頁碼連結。分享首頁後，接收者從封面開始閱讀。

第一版不包含公開註冊、多使用者、自由畫布、自訂程式碼及網域管理介面。

## 2．整體視覺

採用有留白的紙本作品集風格：

| 項目 | 設計 |
|---|---|
| 書頁 | 暖白 `#FDFBF7`，極淡紙張紋理 |
| 文字 | 墨黑 `#2C2C2C`，輔助文字使用中灰 |
| 書外背景 | 淺暖灰，讓紙頁邊界清楚 |
| 字體 | 標題使用襯線風格；正文與操作介面使用易讀黑體 |
| 圖片 | 保留作品原色，重要圖片不任意裁切 |
| 立體效果 | 輕微書脊陰影、紙頁厚度、翻動時的柔和光影 |
| 操作介面 | 小型工具列，固定位置，避免遮住作品 |

不使用自動播放影片、背景音樂或持續晃動的翻頁提示。首次進入時顯示一次簡短操作提示，操作後消失。

## 3．內容結構

閱讀順序：

**封面 → 目錄 → 關於 Liam → 作品章節 → 聯絡封底**

封面顯示姓名、作品集名稱、一句定位與主視覺，提供「開始閱讀」和「查看目錄」。

每件作品依內容需要使用以下結構：

1. **開場：** 作品名稱、主圖、年份、角色、簡短介紹。
2. **背景：** 任務、問題、限制與目標。
3. **過程：** 關鍵判斷、草圖、研究或迭代。
4. **成果：** 完成畫面、細節與實際結果。
5. **回顧：** 收穫、反思及相關外部連結。

這些章節可省略或重排，不強迫每件作品使用相同篇幅。成果資料由 Liam 提供，不補寫未確認的數字或經歷。

目錄可隨時開啟，列出作品縮圖、名稱與年份；選取後直接跳到作品開場，不播放一連串中間翻頁。

## 4．長篇介紹的分頁規則

採用「結構化內容＋自動分頁＋人工指定分頁點」。

後台編輯的是標題、段落、圖片、圖說、圖組、引言、影片與連結等內容區塊。系統按實際可用空間排列，Liam 可以加上「從新頁開始」。

具體規則：

- 標題至少與下一段的開頭一起出現。
- 圖片和圖說保持在同一頁。
- 一般段落盡量完整保留；過長時按文字行拆分，頁首、頁尾盡量各保留至少兩行。
- 圖組優先整組排列；放不下時改成逐張呈現。
- 大圖可獨占一頁，不把所有圖片壓成小縮圖。
- 每件作品從新頁開始；桌機優先從右頁開始，必要的左頁留白不帶到手機。
- 不以縮小正文字體解決內容溢出。
- 手動分頁與內容過量發生衝突時，允許增加續頁，後台顯示提示。

桌機與手機使用相同內容，分別產生適合該裝置的分頁。頁數可以不同，因此閱讀進度以「作品＋段落」定位，避免旋轉手機後跳到不相關內容。

例如，同一件長篇作品可能在桌機呈現為六頁，手機呈現為十頁；實際數量由文字長度、圖片與字級決定。

## 5．桌機：雙開頁閱讀

預設在可用寬度至少 1024px、可用高度至少 640px 時顯示雙頁。封面和封底置中單獨呈現，內頁左右展開。空間不足或瀏覽器放大後，改為單頁。

正文以約 18px 為起點，優先確保閱讀舒適度；書本不會為了塞進螢幕而無限縮小。內容超出書頁可用高度時，可在書頁內上下捲動閱讀，不會為了動畫而裁掉文字。

當内容超過顯示尺寸時，加上滾動功能

操作方式：

| 操作 | 行為 |
|---|---|
| 點擊書外左右箭頭 | 上一組／下一組雙頁 |
| 拖動外側下方頁角 | 跟隨滑鼠翻頁；未超過門檻時回彈 |
| 點擊目錄作品 | 直接切換到對應開場 |
| 點擊圖片 | 開啟大圖檢視 |
| 滑鼠滾輪／觸控板 | 保留一般捲動，不觸發翻頁 |
| 選取文字 | 正常選取、複製 |

**只有指定頁角能開始拖曳翻頁。** 正文、圖片、連結與影片區域不註冊整頁拖動，避免和文字選取、媒體操作衝突。

一般翻頁動畫約 450 毫秒，使用紙頁彎折、透視和陰影；快速連按時限制動畫佇列，避免失控跳頁。

## 6．手機：單頁閱讀

手機維持單頁，即使橫向使用，也不強制切成雙頁。

- 文字依手機寬度重新排版。
- 底部固定顯示「目錄／上一頁／進度／下一頁」。
- 所有主要按鈕至少提供 44 × 44px 的操作區域。
- 內容區保留上下捲動、文字長按和系統手勢。
- 在頁面底部、與正文分開的翻頁區，可以左右滑動切頁。
- 不從螢幕最邊緣啟動翻頁，避開手機系統的返回手勢。

一般狀態按螢幕高度分頁。使用者放大字體、放大瀏覽器或螢幕高度過小時，當頁允許垂直捲動，完整保留內容。

手機翻頁動畫縮短至約 300 毫秒，降低透視幅度。

**縮放分成兩種：**

- **文字閱讀：** 提供標準／大／特大字級，調整後重新分頁，保留目前閱讀段落。保留瀏覽器原生雙指縮放。
- **圖片檢視：** 點圖進入全螢幕，可雙指縮放與拖動；另有放大、縮小、重設和關閉按鈕。圖片檢視開啟時暫停書本翻頁手勢，關閉後回到原頁。

## 7．鍵盤、動態效果與輔助閱讀

當焦點位於書本閱讀區時：

| 按鍵 | 行為 |
|---|---|
| ←／→ | 上一頁／下一頁；雙頁模式切換一組雙頁 |
| Home／End | 封面／封底 |
| Tab | 依序移動到可操作項目 |
| Enter／空白鍵 | 啟動目前聚焦的按鈕 |
| Esc | 關閉目錄、設定或大圖檢視 |

焦點在輸入欄位、影片控制或其他元件時，不攔截其原有按鍵。

其他要求：

- 焦點有清楚外框。
- 對話框開啟後管理焦點；關閉後返回觸發按鈕。
- 翻頁完成後向螢幕閱讀器簡短播報作品與頁次。
- 動畫產生的重複頁面不進入輔助閱讀順序。
- 圖片提供替代文字，裝飾紋理略過朗讀。
- 跟隨系統「減少動態效果」設定，並提供網站內切換；啟用後直接切頁，取消 3D 翻動與回彈。

另提供「連續閱讀」選項，將同一份作品內容排成可上下捲動的長頁，方便放大閱讀與輔助工具使用。切換時保留目前作品位置。

驗收參照 WCAG 2.2 的鍵盤、重排與動態效果相關要求；實作後仍需測試，才可判斷符合程度。[W3C 規範](https://www.w3.org/TR/WCAG22/)

## 8．Liam 的編輯後台

後台以桌機操作為主，手機可修改文字、排序及發佈。

桌機採三區布局：

- **左側：** 封面、關於、作品清單、聯絡與全站設定。
- **中央：** 目前內容的編輯區。
- **右側：** 預覽，可切換桌機雙頁／手機單頁。

保留六類頁面樣式：作品開場、文字頁、整頁圖片、圖文頁、圖組頁、影片頁。可調整內容順序、圖片焦點和分頁點，版面由既定規則處理。

編輯操作：

- 停止輸入約一秒後自動儲存，也提供手動儲存。
- 明確顯示「儲存中／已儲存／儲存失敗」。
- 儲存失敗時保留目前輸入，提供重試。
- 有未儲存變更時，離開頁面前提醒。
- 圖片上傳顯示進度，可填寫圖說、替代文字與裁切焦點。
- 發佈前檢查缺少圖片、必要欄位、無效連結格式及排版溢出。
- 多分頁同時編輯時偵測版本衝突，避免較舊內容靜默覆蓋新內容。

預覽需要 Liam 登入，不提供公開草稿連結。

## 9．草稿、發佈與回復

資料分為「可修改草稿」與「不可變更的已發佈快照」。

**儲存草稿 → 檢查與預覽 → 發佈確認 → 建立快照 → 切換公開版本**

具體行為：

1. 編輯與儲存只更新草稿。
2. 點擊發佈後，顯示此次新增、修改與移除的內容摘要。
3. 系統確定指定草稿版本已儲存，並檢查媒體是否準備完成。
4. 建立包含文字、圖片引用、排序、主題和排版規格的完整快照。
5. 以一次資料庫交易切換「目前公開版本」。
6. 成功後顯示發佈時間；失敗時保留原公開版本。

正在閱讀的訪客繼續使用已載入版本，避免閱讀途中頁數改變；重新整理或下一次造訪時讀取新版本。

第一版公開入口每次取得目前版本，內容與圖片按版本快取，避免入口的舊快取妨礙發佈生效。

版本紀錄提供預覽和「設為公開版本」。回復舊版只改變公開版本，不覆蓋目前草稿。歷史版本先採手動清理，任何仍被保留版本引用的圖片均不得刪除。

## 10．技術與資料方案

建議使用單一網站應用，將維護範圍集中：

| 層級 | 選擇與用途 |
|---|---|
| 網站與後台 | Next.js App Router |
| 編輯器 | TipTap，儲存結構化內容 |
| 區塊排序 | dnd-kit，並提供上下移動按鈕 |
| 樣式 | CSS Modules＋統一樣式變數 |
| 資料與登入 | Supabase PostgreSQL＋Auth |
| 圖片與文件 | Supabase Storage |
| 網站託管 | 延用 README 的 Netlify 方向，上線前驗證部署相容性 |

後端操作集中在 Next.js 的伺服器端功能與 API；第一版取消獨立 Express／NestJS、Render 後端和 Cloudflare 網域 API。

Next.js 提供伺服器端資料修改與快取更新機制，可支援內容更新流程。[官方文件](https://nextjs.org/docs/app/getting-started/mutating-data)

核心資料包含：

- **Site：** 全站識別與目前公開版本。
- **Draft：** 草稿內容、主題、修訂編號及儲存時間。
- **Publication：** 完整內容快照、格式版本與發佈時間。
- **Asset：** 檔案、尺寸、替代文字及處理狀態。
- **PublicationAsset：** 公開版本使用哪些檔案。

每件作品、章節和內容區塊都有穩定識別碼，供重新分頁與閱讀位置映射使用。

登入僅允許預先建立的 Liam 帳號，關閉公開註冊。每個寫入操作都驗證身分；草稿及原始素材使用私人存取權限。已發佈圖片另以公開衍生檔提供，未發佈素材不混入公開媒體庫。Supabase 的資料與檔案權限透過相應的存取規則控制。[Storage 權限文件](https://supabase.com/docs/guides/storage/security/access-control)

## 11．載入、搜尋與故障處理

- 首次載入優先顯示封面與必要字體，再預載相鄰頁面圖片。
- 圖片提供符合裝置大小的版本，事先保留尺寸以減少版面跳動。
- 影片點擊後才載入播放器，翻離該頁時暫停播放。
- 公開文字保留為可選取的 HTML，動畫只處理呈現效果。
- 搜尋引擎取得公開作品文字；全站使用同一首頁網址和分享封面。
- 字體或裝置尺寸改變時重新排版，維持內容位置。
- 圖片載入失敗時保留版面，提供重試。
- 動畫失效時保留按鈕切頁；無 JavaScript 時提供基本連續閱讀。
- 系統錯誤不可自動切換到草稿作為替代內容。

營運成本主要包括網域、網站託管、資料庫和圖片流量。方案額度與費用在部署前按實際作品素材量確認；資料庫與媒體都需要備份及回復驗證。

## 12．實作順序與驗收

| 階段 | 交付與通過條件 |
|---|---|
| ① 閱讀原型 | 使用一件代表性長篇作品，驗證雙頁、單頁、自動分頁、文字選取、大圖與鍵盤操作 |

必須通過的核心情境：

- 修改草稿後，公開網站仍顯示原內容。
- 發佈成功後，新開啟的網站顯示完整新版本。
- 發佈失敗時，不出現新舊內容混合。
- 回復版本後，內容與圖片一併回復。
- 長文、大字級和手機旋轉均不遺失或裁切內容。
- 文字選取、上下捲動及圖片縮放不誤觸翻頁。
- 鍵盤可完成閱讀；減少動態效果時無 3D 動畫。
- 未登入者無法讀取草稿或修改資料。
- 切換作品與頁碼，全程不產生作品分享網址。

審核通過後，先製作閱讀原型確認翻書手感與長文排版，再完成後台與正式發佈系統。
